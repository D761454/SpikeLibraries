# Contributing Guidelines

## Use Issues

We would prefer for issues to be used for almost everything. 
- Need help with one of the libraries?
- Want to suggest a feature or modification?
- etc.

Open an Issue.

For other problems, please prefer using the [Discussion Forums](https://github.com/D761454/SpikeLibraries/discussions) instead.

## How to open Issues

You may use the Issue Tracker to submit bug reports, feature requests or suggestions. You may ask for help or advice as well. 
However, PLEASE CAREFULLY READ THIS! ISSUES IGNORING THESE GUIDELINES MAY BE CLOSED AND USERS MAY BE BLOCKED!

1. Please clarify the request as best you can.
2. Please be kind. Impolite, entitled or simply rude request may lead to bans.
3. Please use the TEMPLATES provided based on the scope of your request / issue.
4. Try to be as explicit as you can with the ideal outcome and what has been tried already.
5. If there is an asset or crash, please provde a debugger callstack as these are invaluable.
6. Please state if any modifications have been made to the library in question.

As these libraries are Open-Source, lazy or minor issues may be ingored or sidelined.

Brief warning:

If your GitHub account is anonymous and was created five minutes ago your post will receive more 
scrutiny and incomplete questions will be dismissed.

If you have been using the libraries / C++ for an extended period (several years+) or have 
deonstrated good behaviour, it is ok to not fulfill every requirement. The guidelines are meant for newer users as 
experienced users are likely to know what info is useful within their specific context.

## How to open Pull Requests

- Please note that through doing submitting a pull request you also request that your code is reviewed and then taken into the libraries forever. The pull request should be created in the interest of users and to ensure its goal and changes are made clear so it may be accepted.
- On feature addition, please provide info on the use-case.
- Please provide images / video where applicable to demonstrate a feature quickly.
- If you create a pull request and intend to continue work, please create a separate branch for this as within Git, a pull request is associated with the branch it was generated on, meaning new commits are included within the pull request.
